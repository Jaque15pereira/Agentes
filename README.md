# 📊 Plano Personalizado — Analista de Business Intelligence (BI) + IA

---

## 🧩 Visão do Dia a Dia
Como é o trabalho de um(a) Analista de BI:
- Extrair e transformar dados de diferentes fontes
- Criar dashboards e relatórios para apoiar decisões
- Analisar tendências e padrões nos dados
- Trabalhar em conjunto com áreas de negócio para entender necessidades
- Garantir qualidade e consistência das informações

---

## 🧠 Mapa de Skills

**Core Skills (essenciais):**
- SQL e manipulação de dados
- Modelagem de dados e ETL
- Visualização de dados (Power BI, Tableau)

**Nice-to-Have (complementares):**
- Estatística aplicada
- Fundamentos de Machine Learning

**Ferramentas e Tecnologias:**
- Power BI
- SQL Server / MySQL
- Excel avançado

---

## 📅 Roadmap de 90 Dias (10h/semana)

### Mês 1 — Fundamentos
**Semana 1-2:**
- Lógica de programação básica (variáveis, loops, funções)
- Introdução a bancos de dados relacionais e SQL  

**Semana 3-4:**
- Consultas SQL (SELECT, JOIN, GROUP BY)
- Conceitos de BI e ciclo de dados (ETL, Data Warehouse)

### Mês 2 — Prática
**Semana 5-6:**
- Dashboards simples no Power BI
- Conectar diferentes fontes de dados (Excel, SQL, CSV)  

**Semana 7-8:**
- Boas práticas de visualização de dados
- Estatística descritiva aplicada a BI

### Mês 3 — Portfólio e Preparação
**Semana 9-10:**
- Projeto completo de BI (ETL + Dashboard)
- Documentar processo e insights  

**Semana 11-12:**
- Simular entrevistas técnicas
- Revisar conceitos e consolidar portfólio

## 💬 Roteiro de Entrevistas

1. **O que é Business Intelligence?**  
   → BI é o processo de transformar dados em informações úteis para apoiar decisões estratégicas.  

2. **Diferença entre relatório e dashboard?**  
   → Relatório é estático e detalhado; dashboard é dinâmico e interativo.  

3. **Como garantir qualidade dos dados?**  
   → Validando fontes, aplicando regras de limpeza e verificando consistência.  

4. **Experiência com SQL?**  
   → Cite exemplos práticos de consultas, joins e agregações.  

5. **Como explicar um insight para alguém não técnico?**  
   → Usar linguagem simples, focar no impacto no negócio e mostrar visualizações claras.
